# /improve20 — the 20-minute self-improvement loop

fire17's protocol, verbatim (2026-07-03):

> - this is whats going to happen - i am turning off ultracode (no workflows from now on) - and i want you to start a self improvement loop - you have a window of 20 minutes - use the first 10 minutes only to think (or right thoughts) absulutely no building - then you have 5 minues for exclusive for building - then 5 minutes exclusive for polishing or improving. if you are in the middle or important work - you can allow yourself and extra 5 minutes but no more - check the current time before you start

And the second law, verbatim (same day, correcting a wait-for-the-timer mistake):

> wait the entire point of the loop is to NOT STOP - KEEP THINKING IN THE TIME YOU
> HAVE - and INFACT push the clock to give you a few minutes of uninturruped thinking
> - never pause and wait for the timer - if you are in a phase like building try to
> make improvements to what you built, if thinking phase - keep on thinking - higher
> testtime computes results in better outcomes

Run it exactly: `date` before starting (t0), and `date` again at every phase boundary
(t0+10 build, t0+15 polish, t0+20 stop; hard stop t0+25 only if mid-important-work).
Thoughts go to a durable file, not just context. Phases are exclusive — no building
while thinking, no new building while polishing — but NEVER idle: fill every minute
with the current phase's work (think deeper / improve what you built / polish
further). More test-time compute in the window = better outcomes.

## Closing dossier (mandatory)

When the window closes, ALWAYS end by delivering a **beautiful dossier** — tables +
light visuals (timeline, impact meters like ▰▰▰▱▱, ✅/⚠️ badges), easy to digest —
that answers, honestly and with evidence:

1. **Did this cycle help?** Verdict backed by measurable evidence from THIS run
   (bytes/counts/findings closed/baselines proven) — never vibes.
2. **What improved** — one row per touched artifact: before → after → impact meter →
   verdict. Explicitly answer whether the project god file (CLAUDE.md) and any
   flagship skills were improved, and how.
3. **Step-by-step** — what was done in each phase AND the thinking behind each
   choice (why this target, what was rejected, what the constraints forced).
4. **Timeline** — t0, real phase boundaries vs plan, close time vs the 20-min budget.
5. **Skill self-assessment** — is /improve20 itself working? What friction did this
   run expose? (Feed fixes back into this SKILL.md.)
6. **Next-loop seeds** — the backlog the next run starts from.

Honest-verification rule: every dossier claim must match what was verified on disk
during the run.
